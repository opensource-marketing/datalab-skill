# 한국관광 데이터랩 스킬

한국관광공사 [한국관광 데이터랩](https://datalab.visitkorea.or.kr)의
관광 데이터를 **웹사이트에 접속하지 않고** 쓰기 위한 에이전트 스킬 모음입니다.

"강릉에 호텔 지을 만해?", "작년에 일본인이 가장 많이 간 시군구 10곳",
"의료관광 환자가 어느 나라에서 오나" 처럼 평소 쓰는 말로 물으면
표나 HTML 리포트로 답합니다.

검증된 지표 **348개**를 담고 있습니다. 실제로 호출해 보고 값을 산술로
교차 확인한 것들입니다. 이름만 아는 미검증 지표 517개는 따로 색인에
두었습니다.

## 설치

```bash
npx skills add opensource-marketing/datalab-skill
```

현재 프로젝트에 설치됩니다. 처음이라면 이 한 줄이면 됩니다.

| 명령 | 효과 |
|---|---|
| `npx skills add opensource-marketing/datalab-skill -g` | 전역 설치 (모든 프로젝트에서 사용) |
| `npx skills list` | 설치된 스킬 조회 |
| `npx skills update` | 최신 릴리스로 업데이트 |
| `npx skills remove opensource-marketing/datalab-skill` | 제거 |

[Agent Skills CLI](https://github.com/vercel-labs/skills)가 지원하는
에이전트에서 동작합니다. 스킬들은 서로를 부르는 한 세트이므로
**전부 설치하세요** — 하나만 골라 넣으면 나머지를 찾지 못합니다.

설치 후 아무것도 설정할 필요가 없습니다. 곧바로 물어보면 됩니다.

## 어떻게 쓰는가

스킬을 직접 고르지 않아도 됩니다. 하고 싶은 말을 그대로 하면
에이전트가 알맞은 스킬로 넘깁니다.

```
"강릉시 관광시장 어때? 호텔 지을 만해?"
"강릉 속초 양양 중에 어디가 나아?"
"제주도에 누가 오는지 알려줘"
"작년에 일본인이 가장 많이 간 시군구 10곳"
"면세점인데 어느 나라를 노려야 해?"
"중국인 관광객 노린 매장, 서울에서 어디가 좋아?"
"의료관광 환자 어느 나라에서 오나"
"MICE 시장 규모 얼마야"
"정선군 인구감소가 얼마나 심각해?"
"관광 불편신고가 어디서 많이 나와?"
```

무엇을 물어야 할지 모르겠으면 **"데이터랩으로 뭘 할 수 있어?"** 라고
물어보세요. 안내 스킬이 받아서 길을 잡아 줍니다.

## 무엇이 들어 있나

### 기반 세 가지

| 스킬 | 하는 일 |
|---|---|
| **datalab-guide** | 안내 창구. "뭘 할 수 있어", "어떤 데이터가 있어", "왜 값이 안 나와" 처럼 어디서 막혔는지 모를 때 가장 먼저 씁니다. 질문을 알맞은 스킬로 넘겨 주고, **데이터랩이 답할 수 없는 질문은 그렇다고 말해 줍니다** |
| **datalab-query** | 특정 숫자·표·순위가 필요할 때. "강릉시 작년 방문자 몇 명", "외국인 카드소비 1위 지역" 처럼 리포트가 아니라 값 하나를 볼 때 가장 빠른 길입니다. 전국 시군구 순위도 냅니다 |
| **datalab-fetch** | 데이터를 실제로 가져오는 계층. 나머지 스킬들이 이것을 통해 데이터랩을 부릅니다. 카탈로그 348개와 지역·국가 코드표가 여기 있습니다 |

### 리포트 아홉 가지

물음의 종류에 따라 나뉩니다. 전부 HTML 리포트를 만듭니다.

**지역을 볼 때**

| 스킬 | 어떤 물음에 |
|---|---|
| **region-market-scan** | "여기 출점해도 될까" — 시군구의 관광시장을 수요·매력·공급 세 면에서 스캔합니다. 한 곳을 깊게 보거나, 여러 곳을 나란히 놓고 견줍니다 |
| **region-visitor-profile** | "누가 오는가" — 그 지역에 누가·어디서·언제·얼마나 머무르며 무엇에 돈을 쓰는지 봅니다. 숙박·외식·리테일 출점 검토와 지역 마케팅에 씁니다 |
| **region-vitality-brief** | "이 지역이 버티고 있나" — 인구·고령화·재정자립도 같은 지역 체력과, **주민 한 명이 떠난 자리를 메우려면 관광객 몇 명이 와야 하는지**를 함께 봅니다. 지자체 정책·지역소멸 판단에 씁니다 |

**해외 관광객을 볼 때**

| 스킬 | 어떤 물음에 |
|---|---|
| **inbound-country-brief** | "어느 나라에 예산을 쓸까" — 방한 인바운드 타겟 국가를 업종별로 평가해 점수를 냅니다. 면세점·호텔·여행사처럼 업종이 다르면 답도 달라집니다 |
| **inbound-region-scan** | "그 나라 사람들이 어디로 가나" — 국가를 정해 놓고 어느 시군구가 후보인지 찾습니다 |
| **global-social-brief** | "해외에서 뭐라고 하나" — 방문이나 소비가 아니라 **소셜미디어의 말(buzz)** 을 봅니다. 어느 나라가 많이 언급하는지, 어떤 해시태그가 도는지 |

**시장 전체나 특정 분야를 볼 때**

| 스킬 | 어떤 물음에 |
|---|---|
| **national-tourism-brief** | "지금 관광 시장 어때" — 특정 지역이나 국가가 아니라 전국 판을 한 장으로 봅니다 |
| **theme-market-brief** | 고부가 테마 하나를 깊게 — 의료관광·MICE·한류관광·야간관광·크루즈관광 중 하나를 골라 시장을 정리합니다 |
| **tourism-service-brief** | "무엇이 잘못되고 있나" — 규모나 매출이 아니라 **서비스 품질과 민원**을 봅니다. 관광 불편신고, 소비자 상담, 안내소에 들어오는 질문, 숙소 평가 |

## 결과가 어디에 저장되나

명령을 실행한 디렉토리 아래 `.datalab/` 이 생기고, 받아 온 응답이
그 안에 캐시됩니다. 같은 조건을 다시 물으면 캐시에서 답하므로 빠릅니다.

**`.gitignore` 에 `.datalab/` 을 넣어 두세요.** 캐시가 11MB 넘게
자랍니다.

다른 곳에 두고 싶으면 `DATALAB_HOME` 환경변수로 옮길 수 있습니다.

```bash
export DATALAB_HOME=~/datalab-cache
```

## 알아 둘 것

**지표 이름은 출처이지 근거가 아닙니다.**

컬럼 이름이 "방문자수"인데 값은 집중률(%)인 지표가 실제로 있습니다.
이름이 "숙박시설"인데 값은 객실 수라 27배 차이 나는 것도 있습니다.
가장 크게 어긋난 것은 컬럼 이름이 "방한 관광객수"인데 값은 그 해
**세계** 국제관광객 도착수인 지표입니다 — 이름만 믿으면 90배 부푼
숫자를 "방한객"으로 쓰게 됩니다.

그래서 카탈로그에 넣기 전에 실제로 호출해 보고 산술로 교차 확인했고,
확인된 함정은 지표마다 `caution` 으로 적어 두었습니다. **리포트와 표에
그 주의사항이 함께 실립니다** — 숫자만 떼어 옮기지 마세요.

**0이 값이 아닐 수 있습니다.** 인구감소지역 지표 일부에서 데이터랩은
결측을 0으로 줍니다. 그대로 그리면 그 지역만 재정이 무너지고 아이가
안 태어난 것처럼 보입니다.

**빈 결과에는 여러 이유가 있습니다.** "값이 없다", "아직 발표되지
않았다", "그 조건으로는 부를 수 없다" 는 서로 다릅니다. 스킬이
구분해서 말해 줍니다.

## 요구사항

- Python 3.9 이상
- `pip install "PyYAML>=6.0" "pandas>=2.0"`

HTTP 는 `curl` 서브프로세스로 부릅니다. SSL 인터셉트 프록시 환경에서
Python 의 TLS 처리가 실패할 수 있는데 curl 은 견디기 때문입니다.
데이터랩에 부담을 주지 않도록 호출 사이에 0.5초를 둡니다.
