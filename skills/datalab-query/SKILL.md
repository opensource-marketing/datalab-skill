# 데이터랩 임의 조회

리포트 Skill(`inbound-country-brief`, `region-visitor-profile`)은 미리 정한
질문에만 답한다. 이 Skill은 사용자가 그때그때 던지는 질문에 답한다.

## 두 가지 도구

| 묻는 형태 | 도구 |
|---|---|
| "이 지역/국가의 값은?" | `query.py` |
| "어느 지역이 1등인가?" | `rank.py` |

## 세 단계로 한다

### 1단계 — 지표를 찾는다

qid를 외우거나 추측하지 마라. 색인에서 찾는다.

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/index.py search 숙박 사업체
```

결과의 표시를 반드시 읽어라.

| 표시 | 뜻 | 어떻게 다루나 |
|---|---|---|
| `[검증됨:지역]` `[검증됨:인바운드]` `[검증됨:공급]` `[검증됨:테마]` | 실호출로 확인했고 컬럼 의미도 안다 | 그대로 쓴다 |
| `[미검증]` | 사이트 JS에서 이름만 긁어 왔다 | 조회는 되지만 **컬럼 의미도 축도 단정하지 마라** |
| `[미검증·주석]` | 사이트가 화면에 그리지 않는 지표 | 특히 조심한다 |

### 2단계 — 조회한다

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_04_01_022 --region 강릉시 --from 202401 --to 202412
```

비교하려면 `--region`이나 `--country`를 여러 번 준다. `조회대상` 컬럼이 붙는다.

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_04_01_022 --region 강릉시 --region 속초시 --region 양양군 \
  --from 202401 --to 202412 --sort 방문자수 --desc
```

| 옵션 | 쓸 곳 |
|---|---|
| `--region` / `--country` | 이름도 코드도 된다. 여러 번 쓰면 비교표 |
| `--sido` | 시도명 또는 두 자리 코드. 야간관광처럼 **시도 축** 지표에 쓴다 |
| `--attraction` | `지역:이름` 형식. 관광지 축(`LN_05_*`) 지표에 쓴다 |
| `--festival` | 축제 이름 또는 `FSTV_ID`. 축제 축(`FE_*`) 지표에 쓴다 |
| `--marine-region` | 해양관광 지표에 쓴다. 연안 유형을 먼저 물어 배열 파라미터를 만든다 |
| `--from` `--to` | `YYYYMM`. 지표가 연 단위면 자동으로 연도만 보낸다 |
| `--param K=V` | 지표 고유 파라미터. 빈 결과가 나올 때 여기서 조절한다 |
| `--sort` `--desc` | 정렬. 없는 컬럼이면 정렬하지 않고 알려 준다 |
| `--format` | `table`(기본) / `md` / `csv` / `json` |
| `--limit` | 표에 보일 행 수(기본 30). `0`이면 전부 |
| `--out` | 파일로 저장 |

### 3단계 — 결과를 읽고 답한다

머리말은 **보낸 조건만** 적는다. 결과가 그 조건으로 좁혀졌다고 단언하지
않는다. 이유는 아래 "축을 무시하는 지표"를 보라.

사용자에게 답할 때는 표를 그대로 붙이기보다 **숫자가 무엇을 말하는지**
먼저 쓰고 표를 근거로 붙여라. 출처 문구는 반드시 남긴다:
`출처: 한국관광공사 한국관광 데이터랩(datalab.visitkorea.or.kr)`

## 순위를 물어보면 — rank.py

지역을 정해 놓고 묻는 대신, 지표 하나를 전국 시군구로 훑어 순위를 낸다.

```bash
# 일본인 방문자가 가장 많은 시군구
python3 {SKILLS_DIR}/datalab-query/scripts/rank.py \
  --qid LN_03_01_067 --column 방문자수 --where 국적=일본 \
  --from 202401 --to 202412 --top 20
```

| 옵션 | 설명 |
|---|---|
| `--column` | 순위를 매길 컬럼의 **한글 라벨**(카탈로그 라벨) |
| `--agg` | `sum`(기본) / `mean` / `max` / `min` / `last` |
| `--where 컬럼=값` | 집계 전에 거를 행 조건. 여러 번 쓸 수 있다 |
| `--sido` | 한 시도로 좁힌다. **없으면 전국 271곳을 훑는다** |
| `--top` | 상위 개수(기본 20). `0`이면 전부 |

### 시간이 오래 걸린다

시군구 하나마다 한 번씩 부른다. 지표 하나만 부르므로 지역당 0.6초쯤이고,
**전국 271곳이면 3분쯤** 걸린다(2026-08-23 실측: 전남 22곳 14초). 같은
조건을 다시 부르면 캐시에서 나온다.

지역마다 지표 여러 개를 부르는 스킬은 훨씬 오래 걸린다 —
`inbound-region-scan` 은 지역당 4~5초라 전국이면 20분쯤이다
(충북 15곳 66초).

사용자에게 먼저 알려라. 후보 지역이 정해져 있으면 `--sido`로 좁히거나
`query.py --region`을 여러 번 쓰는 편이 훨씬 빠르다.

### 비율 컬럼은 더하지 않는다

`--agg sum`을 비율(%) 컬럼에 쓰면 **거부한다.** 지역끼리 비율을 더하면
뜻이 없는데 숫자는 나오기 때문에 틀린 줄 모른다. 비율을 보고 싶으면
`--agg mean`을 쓰되, 그것도 지역 규모를 무시한 단순평균임을 밝혀라.

### 빠진 지역을 감추지 않는다

값이 안 나온 지역은 사유와 함께 `미수록`에 남는다. "전국 271곳 중 값이
나온 곳 268곳"처럼 표시되니, 사용자에게 답할 때 그 숫자를 함께 전하라.

## 지역·국가 코드 찾기

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/codes.py region 강서
python3 {SKILLS_DIR}/datalab-fetch/scripts/codes.py sido 강원
python3 {SKILLS_DIR}/datalab-fetch/scripts/codes.py country 베트남
python3 {SKILLS_DIR}/datalab-fetch/scripts/codes.py festival 아리랑
```

이름이 여러 곳에 걸리면 `query.py`가 **거부하고 후보를 보여 준다.**
임의로 하나를 고르지 않는다 — 사용자가 묻지 않은 지역의 숫자를 보여 주는
것이 빈손으로 돌아가는 것보다 나쁘다. 후보를 사용자에게 보여 주고 물어라.

## 조회 축이 지표마다 다르다

같은 `SGG_CD` 자리에 어떤 지표는 시군구 다섯 자리를, 어떤 지표는 시도 두
자리를 받는다. **틀리면 오류가 아니라 빈 배열이 온다.** 그래서 원인을
놓치기 쉽다.

| 축 | 쓰는 옵션 | 해당 지표 |
|---|---|---|
| 시군구(5자리) | `--region` | `LN_*`, `BZM_*` |
| 시도(2자리) | `--sido` | `BY_TH_NIGHT_TOUR_*` |
| 관광지(CONT_ID) | `--attraction` | `LN_05_*` |
| 축제(FSTV_ID) | `--festival` | `FE_*` |
| 해양(배열 파라미터) | `--marine-region` | `BY_TH_MARINE_*` |
| 국가 | `--country` | `NAT_*` |
| 없음(전국 고정) | 아무것도 안 준다 | `BY_TH_MEDIC_*`, `NAT_05_*` |

행이 안 나오면 축부터 의심하라. 색인 검색 결과의 `조회축` 줄이 힌트를 준다.

## 관광지 하나를 물어보면

관광지 코드(`CONT_ID`)는 고정 표가 없다. 전국 관광지가 수천 개라
데이터랩이 목록을 통째로 내려주지 않기 때문에 **지역을 좁혀 찾아야 한다.**

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/poi.py 경포 --region 강릉시
# 125790  강릉경포대            역사유적지
# 128758  강릉경포해수욕장      자연경관(하천‧해양)
```

찾았으면 `--attraction "지역:이름"`으로 조회한다. 두 곳을 나란히 놓을 수도 있다.

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py --qid LN_05_02_002 \
  --attraction "강릉시:강릉경포해수욕장" --attraction "강릉시:강릉중앙시장" \
  --from 202401 --to 202412
```

**이름이 여러 곳에 걸리면 거부하고 후보를 보여 준다.** "중앙시장"만 해도
여러 지역에 있고, 한 지역 안에서도 "경포"는 네 곳에 걸린다. 후보를
사용자에게 보여 주고 물어라.

## 해양관광을 물어보면

해양관광(`BY_TH_MARINE_*`)만 **배열 파라미터**를 받는다. 지역의 연안 유형
목록을 함께 보내야 하는데, 그 값은 사이트가 먼저 부르는 지표가 돌려준다.
`--marine-region`이 두 단계를 대신한다.

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid BY_TH_MARINE_001_009 --marine-region 강릉시 --from 202401 --to 202412
```

결과는 **행정동(읍면동) 단위**다. 이 프로젝트에서 가장 촘촘한 지역 단위다.
바다에 닿지 않은 지역은 이유를 말하고 멈춘다.

## 내국인 관광소비를 물어보면

시군구 단위 내국인 카드소비 지표는 데이터랩이 내렸다. 하지만 **시도
단위는 살아 있다.**

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid BY_TH_NIGHT_TOUR_002_002 --sido 강원 --from 202401 --to 202412
```

`전체_관광소비액`(원)이 현지인·외지인·외국인·내국인으로 나뉘어 온다.
`야간_소비액`은 그중 야간 몫이다. **구분 행을 모두 더하지 마라** —
현지인 + 외지인 = 내국인이라 두 번 세게 된다(12개월 검산 확인).

## 축을 무시하는 지표가 있다

`NAT_08_01_021`(국가별 방한객수)은 `natCd`를 받지만 **무시한다.**
의료관광 계열(`BY_TH_MEDIC_*`)은 아예 지역·국가 축이 없어 전국 값만 준다
(사이트 JS가 호출 직전에 값을 지우는 것을 코드로 확인했다). 무엇을
넣어도 전체 국가 204행이 그대로 온다. 사이트도 전체를 받아 화면에서 걸러
쓴다. 이런 지표는 카탈로그의 `caution`에 적혀 있고 조회 결과 머리말에
`주의:`로 나온다.

**그래서 "베트남으로 조회했으니 이 표는 베트남 값"이라고 넘겨짚지 마라.**
표에 국가명 컬럼이 있으면 그 컬럼을 보고 해당 행을 골라 읽어라.

## 행이 안 나올 때

데이터랩은 실패를 네 가지로 표현한다. 원인이 다르므로 대응도 다르다.

| 증상 | 원인 | 할 일 |
|---|---|---|
| 행 없음 | 파라미터가 틀렸다 | 머리말의 "알려진 파라미터"를 보고 `--param`으로 맞춘다 |
| 행 없음 | 그 조건에 데이터가 없다 | 조사 대상이 아닌 국가·지역일 수 있다. 기간을 넓혀 본다 |
| 값이 빈 레코드 | 숨은 필수 파라미터 누락 | `--param dispYn=Y` 등을 넣어 본다 |
| 종료코드 4, "0바이트 본문" | 데이터랩이 그 지표를 내렸다 | 다른 지표를 찾는다. 재시도해도 소용없다 |
| 종료코드 3 | 세션 만료 | `datalab-auth` Skill로 넘긴다 |

파라미터를 도무지 모르겠으면 `--region`, `--country` 등 명확한 기본 파라미터부터 시작해라.

## 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 정상 |
| 1 | 입력 문제 (모르는 qid, 없는 지역, 후보 여러 개) |
| 3 | 세션 만료 → `datalab-auth` |
| 4 | 조회는 됐으나 행이 없거나 인출에 실패 |

## 지켜야 할 것

- **컬럼 의미를 지어내지 마라.** `[미검증]` 지표의 컬럼은 원본 영문명 그대로
  나온다. 그것을 한글로 번역해 사용자에게 설명하는 순간 추측이 사실인 척한다.
  뜻을 모르면 모른다고 하고, 알아야겠으면 카탈로그로 옮겨 적는 절차를 밟아라
  (`datalab-fetch` SKILL.md의 "새 지표 찾기").
- **`[미검증]`은 축도 검증하지 않았다는 뜻이다.** `BDT_01_01_001_4`에
  `--sido 강원`(SGG_CD=51)을 보내면 "보낸 조건"에는 강원이 찍히는데
  응답의 `SIDO_NM`은 **전국**이다. 검증된 지표라면 `caution`이 그것을
  적어 두지만 미검증에는 적어 둘 자리가 없다. **응답의 지역·기간 컬럼을
  눈으로 맞춰 보고**, 어긋나면 그 숫자를 쓰지 마라.
- **시군구 축 지표에 `--sido`를 주면 두 자리가 `SGG_CD` 자리로 간다.**
  `LN_04_01_022`는 시도 합계를 주지만(2024-01 강원 11,299,486) 그 시도의
  첫 시군구 값을 주는 지표도 있다. 어느 쪽인지는 응답의 지역명이 말해
  준다 — 조회 결과에 주의가 붙으면 표의 지역명을 확인하라.
- **소비 금액 단위는 컬럼마다 다르다.** 카탈로그의 `unit`을 읽고 그대로 써라.
  같은 지역·기간의 같은 금액을 지표마다 원·천원·백만원으로 준다.
  카탈로그에 `unit`이 없는(미검증) 소비 컬럼은 단위를 단정하지 말고 비율로 읽어라.
- **호출 간 0.5초 간격**이 인출 계층에 내장돼 있다. 우회하지 마라.
- 응답은 작업 공간(기본 `.datalab/data/raw/`)에 캐시된다. 같은 조건
  재조회는 네트워크를 타지 않는다.
- 세션 만료를 만나면 **자동으로 재로그인하려 하지 마라.** 작업을 멈추고
  `datalab-auth` Skill로 넘긴다.

## 기간 쓰는 법

`--period` 로 사람 말을 그대로 쓸 수 있다. `--from`/`--to` 와 함께 쓸 수는 없다.

| 쓰는 말 | 풀리는 기간 |
|---|---|
| `--period 작년` | 지난 달력 연도 전체 |
| `--period 올해` | 올해 1월부터 지난달까지 (지표가 더 짧으면 그 지표까지) |
| `--period 최근12개월` | 지난달부터 거꾸로 12개월 |
| `--period 2024` | 2024-01 ~ 2024-12 |
| `--period 2024상반기` / `2024Q3` | 반기 · 분기 |
| `--period 202401-202412` | 직접 지정 |
| `--period 2024~2025` | 연도 범위 (2024-01 ~ 2025-12) |
| `--period '작년 12월'` / `'올 상반기'` | 상대 연도 + 월·반기 |

**지표마다 데이터가 나와 있는 마지막 달이 다르다.** 아직 발표되지 않은
달을 물으면 데이터랩은 오류가 아니라 빈 배열을 준다. 확인:

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/period.py show 사업체
python3 {SKILLS_DIR}/datalab-fetch/scripts/period.py latest LN_04_01_022
```
