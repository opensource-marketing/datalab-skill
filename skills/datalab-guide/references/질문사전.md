# 질문 사전

`{SKILLS_DIR}` = 이 스킬들이 설치된 디렉토리(이 스킬 폴더의 부모). 소스
저장소와 배포본에서 실제 설치 위치가 다르므로, 아래 명령을 그대로 쓰기
전에 이 값을 자신의 설치 경로로 바꿔라.

사용자가 실제로 던지는 말과, 그 말에 답하는 명령을 짝지어 둔다.
표를 그대로 흉내 내되 지역·국가·기간은 사용자가 말한 것으로 바꾼다.

기간을 말하지 않았으면 `--period 작년` 을 쓴다. 되묻지 않는다 —
초보자에게 "몇 년도요?"는 첫 질문으로 너무 무겁다. 리포트 머리에
기간이 적히므로 사용자가 보고 다시 말할 수 있다.

**사용자가 말한 표현을 그대로 넘겨도 된다.**

- 기간: `2024년` · `24년` · `2024년 1월` · `작년 상반기` · `지난달` · `2024Q3`
- 지역: `강릉` · `서울 중구` · `강원도 강릉시` · `경기 광주`
- 국가: `일본인` · `중국인 관광객` · `타이완`
- 축제·관광지: `화천 산천어축제` · `경포 해수욕장` (띄어 써도 된다)

바꿔 적을 필요가 없다. 특히 **되물은 뒤가 중요하다** — "중구"가 여섯
곳에 걸려 후보를 보여 주면 사용자는 "서울 중구"라고 답한다.


**"강릉 속초 양양 중에 어디?" · "○○랑 △△ 비교해줘"**

```bash
python3 {SKILLS_DIR}/region-market-scan/scripts/compare.py \
  --region 강릉시 --region 속초시 --region 양양군 \
  --period 작년 --out /tmp/compare.html
```

**"제주에 누가 와?" · "방문객이 어디서 오나" · "얼마나 머물러?" ·
"뭘 사?" · "몇 살이 많아?"**

```bash
python3 {SKILLS_DIR}/region-visitor-profile/scripts/visitor_profile.py \
  --region 제주시 --period 작년 --out /tmp/profile.html
```

**"강릉이 다른 데보다 오래 머무나?" · "전국 평균이랑 비교하면?" ·
"여기 외국인은 얼마나 머물러?"** — 방문객 프로파일 리포트의 "전국과
견주면" 표가 답한다. 체류시간과 숙박방문자 비율을 전국 기초지자체
평균과 나란히 놓고 배수를 낸다(강릉시 체류시간 1.5~2.0배).

**체류시간 단위는 분이다.** 2,039분을 그대로 말하지 말고 34시간으로
바꿔 말해라. 외국인은 따로 봐야 한다 — 강릉시는 전체 34시간인데
외국인은 91시간이다.

**"○○ 성수기가 언제야?"** — 방문객 프로파일의 월별 추이를 쓴다.
숫자만 필요하면:

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_04_01_022 --region 강릉시 --period 최근24개월
```

**"크루즈 몇 명 들어왔어?" · "어느 항구로 들어오나?" · "크루즈 관광객
연령대"**

```bash
python3 {SKILLS_DIR}/theme-market-brief/scripts/theme_brief.py \
  --theme 크루즈 --out /tmp/crus.html
```

**두 계열이 있다는 것을 반드시 말해라.** `TS_01_04_*`는 승객과 선원을
함께 세고 `TS_01_05_*`는 입항 기준 항구별 승객을 센다. 같은 달의 값이
다를 수 있고, **서로 빼거나 나누면 안 된다.** 관광객의 연령·성별을
물으면 05 계열이 맞다 — 04는 선원이 섞여 20~30대가 부풀려진다.

**"캠핑장 차릴 만해?" · "○○ 캠핑 수요" · "글램핑 얼마나 있어?"**
— 시장 스캔 리포트의 공급 섹션에 캠핑장 수·사이트 수·유형별 분포가
함께 실린다. 야영장업은 숙박업과 다른 업종이라 숙박 지표에는 없다.
숫자만 필요하면:

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_01_03_003_03_004 --region 강릉시 --from 202401 --to 202412
```

**"○○ 관광 경쟁력 어때?" · "전국에서 몇 위야?" · "여기 관광지로
힘이 있나?"** — 시장 스캔 리포트의 "전국에서의 관광 경쟁력" 표가 답한다.
네 축(관광자원수요·수요강도·다양성·이동거리)의 전국 252곳 중 순위다.
숫자만 필요하면:

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/activate.py \
  axes 51770 --from 202401 --to 202412
```

**"이 지역 인구감소 심각해?" · "관광이 ○○ 먹여 살리나?" ·
"지역소멸" · "관광 대체 효과" · "여기 일자리 중 관광 비중"**

```bash
python3 {SKILLS_DIR}/region-vitality-brief/scripts/vitality_brief.py \
  --region 정선군 --out /tmp/vitality.html
```

**기간이 연 단위다.** `--period 작년` 이 아니라 `--from 2020 --to 2024`
이고, 비우면 2020~2024가 기본값이다. 월을 넣으면 CLI가 거부한다.

리포트의 한 문장은 "**주민 한 명이 떠난 자리를 메우려면 관광객 몇 명이
와야 하는가**"다(정선군: 숙박 42명 또는 당일 106명). 사용자에게 옮길 때
**방문자 수가 아니라는 것**을 반드시 함께 말한다.

앞의 두 지역 스킬과 묻는 것이 다르다:

| 사용자가 알고 싶은 것 | 스킬 |
|---|---|
| 여기 오는 사람은 누구인가 | `region-visitor-profile` |
| 여기서 사업할 만한가 | `region-market-scan` |
| 여기가 버티고 있는가 | `region-vitality-brief` |

## "현지인은 뭘 찾고 외지인은 뭘 찾아?"

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_03_01_045 --region 강릉시 --period 작년
```

내비게이션 검색 기준 관심 업종 비중이 **한 표에 두 열**로 온다
(`현지인_비중`·`외지인_비중`). 강릉은 음식이 현지인 43.9% 대 외지인
40.4%이고 자연관광이 13.3% 대 17.6%다 — 사는 사람과 오는 사람이 같은
도시를 다르게 쓴다. `region-market-scan` 의 '매력' 에도 실린다.

## "우리 지역 소비가 전국에서 몇 퍼센트야?"

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_03_03_058_02 --region 강릉시 --period 작년   # 외지인
```

세 갈래다 — 현지인(`_058_01`) + 외지인(`_058_02`) = 내국인(`_058`).
**외국인은 어디에도 없다.** 현지인 표만 보면 강릉시 2024-01 소비가
1,971 인데 외지인은 55,049 다(28배). 그 표만 옮기면 관광도시를
정반대로 말하게 된다.

## "20대가 많이 가는 관광지는?" · "우리 동네 중심 상권이 어디야?"

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid MM_HO_HOT_001_003_DETAIL --region 강릉시 --period 최근12개월
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid LN_03_01_043 --region 강릉시 --period "2026년 7월"
```

앞은 **세대별 인기관광지 30위**, 뒤는 **중심관광지 100위**(그 지역
관광 동선의 허브)다. 둘 다 `region-market-scan` 의 '매력'에도 실린다.

세대를 좁히려면 `--param AGEG_DIV_CD=20`(20·30·40·50·60 또는 `all`).
**세대마다 표가 완전히 다르다** — 전국 기준 20대는 여의도한강공원,
60대는 코엑스·통도사다.

**`TOTAL_NUM` 은 전국 전체가 아니라 그 표 30곳의 합이다.**
"에버랜드가 전국 검색의 9%"로 읽으면 크게 부푼다.

중심관광지는 **여러 달을 물으면 100행에서 잘린다.** 달을 넘겨
견주려면 한 달씩 부른다. 숙박시설이 관광지와 함께 순위에 든다.

## "우리나라 관광숙박업 객실이 몇 개야?"

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid BZM_07_01_004 --from 2024 --to 2024                    # 전국 추이
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid BZM_07_01_001 --from 2024 --to 2024                    # 시도별
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid BZM_07_01_003 --from 2024 --to 2024                    # 업종별
```

2024년 전국 220,414실 · 2,731개소다. **사업체 수를 보려면
`--param srchGrdTyp=VEND_NUM`** 을 붙인다 — 그러면 응답 컬럼 이름도
`VEND_NUM` 으로 바뀐다.

**모텔·민박은 빠져 있다.** 관광진흥법상 관광숙박업(호텔·콘도)만이라
전체 숙박업(`BZM_03_01_001`, 879,593실)과 네 배 차이가 나는 것이
정상이다. 두 숫자를 같은 표에 놓지 마라.

업종별 표에는 **'합계' 행이 섞여 있다.** 시도별 표는 **16행**이고
광주와 전남이 '전남광주통합특별시' 한 행으로 온다.

## "일본 사람들 여행지에서 한국이 몇 번째야?"

`inbound-country-brief` 리포트의 '그 나라에서 한국은 몇 번째인가'
섹션이 상위 세 나라에 대해 자동으로 붙는다. 한 나라만 보려면:

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/query.py \
  --qid NAT_02_01_006 --country 일본 --from 2021 --to 2021
```

**`RK` 컬럼을 순위로 읽으면 안 된다.** `RK=0` 은 '이 행이 한국'
이라는 표시일 뿐이고 실제 순위는 `RK=1` 부터다 — 일본 2014년은
한국(RK=0) 228만인데 미국(RK=1)이 365만이다. 그대로 읽으면 어느
나라를 물어도 한국이 1위가 된다.

상위 아홉 나라만 오므로 **한국이 그 아래면 순위를 말하지 않는다.**
리포트는 "10위 밖"이라고 적는다 — 숫자를 지어내지 않는다.

**기간 파라미터를 무시한다.** 응답의 `BASE_YEAR` 를 보고 말한다.

## 세그먼트를 묻는 말

**"의료관광 시장 어때?" · "외국인 환자 어디서 오나"**

```bash
python3 {SKILLS_DIR}/theme-market-brief/scripts/theme_brief.py \
  --theme 의료관광 --out /tmp/medic.html
```

**외국인 환자 표가 두 벌이다.** `BY_TH_MEDIC_001_001`·`_003` 은
해마다 **상위 다섯**만 주고(2024년 국가 합 925,094명), `_002`·`_004`
가 전체다(1,170,467명). 상위 다섯만 보고 "전체"라고 적으면 21%가
사라진다. 전체 표에는 **'합계' 행이 섞여 있으니** 걸러라 — 그냥
더하면 두 배가 된다.

의료관광 안에서도 지표마다 시점이 다르다. 관심도·소비액은 지난달까지
있지만 **외국인 환자 수는 2024년까지**다. 환자 수를 물었다면 그 사실을
먼저 알려 준다.

**"MICE 규모" · "부산 야간관광" · "일본에서 한류 얼마나 알아?"**

```bash
theme_brief.py --theme 마이스 --out /tmp/mice.html
theme_brief.py --theme 야간관광 --sido 부산 --out /tmp/night.html
theme_brief.py --theme 한류 --country 일본 --out /tmp/wave.html
```

## 숫자 하나면 되는 말

리포트를 만들지 않는다. 표 하나로 답한다.

**"작년 강릉 방문자 몇 명?"**

```bash
query.py --qid LN_04_01_022 --region 강릉시 --period 작년
```

**"작년 외국인 카드소비 1위 지역은?"**

```bash
python3 {SKILLS_DIR}/datalab-query/scripts/rank.py \
  --qid LN_03_03_059 --column 지역_카드사용액 --period 작년
```

전국 훑기는 271번 호출한다. `--sido` 로 좁힐 수 있는지 먼저 본다.

**"전주 경기전 방문객 어디서 와?"**

```bash
query.py --qid LN_05_01_004_999 --attraction '전주시:경기전' --period 작년
```

관광지 이름은 데이터랩이 쓰는 이름이어야 한다. "전주한옥마을"처럼
사람들이 부르는 이름은 목록에 없을 수 있다. 먼저 목록을 본다:

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/poi.py --region 전주시
```

**"강릉 맛집 어디가 인기야?" · "○○에서 사람들이 많이 찾는 곳"**

```bash
query.py --qid LN_03_01_039 --region 강릉시 --period 작년 --limit 20
query.py --qid LN_03_01_038 --region 강릉시 --period 작년 --limit 20
```

`BDT_03_04_003` 은 같은 지역의 **Top500** 을 준다(039·038은 100개).
더 깊이 볼 때 쓴다 — 다만 값 체계가 달라 섞지 마라. Top500이라도
동점 때문에 501행이 오기도 한다.

`039`는 맛집, `038`은 인기관광지다. **값은 내비게이션 목적지 검색
건수이지 방문자 수가 아니다.** 검색 없이 찾아가는 곳(주민 단골집)은
잡히지 않는다. 그대로 "1위 맛집"이라고 적으면 사실이 아니다.

**"오죽헌 입장객 몇 명?" · "실제로 몇 명이 들어갔어?"**

```bash
query.py --qid LN_03_012_001_001 --region 강릉시 --period 작년
```

**이 저장소에서 유일한 실측치다.** 나머지 방문자 수는 이동통신
기반 추정치인데, 이것은 매표 집계다. 외국인만 보려면 `_003`.

**"동해안 해수욕장 어때?" · "○○ 해양관광 방문자"**

```bash
query.py --qid BY_TH_MARINE_101_002 --marine-region 강릉시 --period 작년
```

해양관광은 `--region` 이 아니라 `--marine-region` 을 쓴다. 지역의
연안 유형을 먼저 물어 배열 파라미터를 만들기 때문이다.

**"해양관광객"이 아니다.** `BY_TH_MARINE_101_001`(연안 읍면동별
방문자)의 값은 그 동의 일반 방문자와 대체로 같다 — 강릉시 21개 동
가운데 17개가 값이 완전히 같았다(2026-08-24 확인). 바다를 보러 온
사람만 골라낸 값이 아니므로 "해양관광객 N명"이라고 적지 마라.
읍면동별 소비(`BY_TH_MARINE_201_001`)는 **원**이고 성·연령 조회의
같은 값은 **천원**이라 나란히 놓으면 1000배 틀린다.

**한 표에 여러 층위가 섞여 온다.** 정선군처럼 내륙인 곳도 빈 배열이
아니라 "정선군 비연안" 행을 주고, 어느 지역을 물어도 "전국 연안"
행이 함께 온다. 구분(`DIV_NM`)끼리 겹치므로 **다 더하면 안 된다** —
"강릉시 연안 어촌"(2024년 3,167,794) 안에 "연안 어촌(강동면)"
(3,026,866)이 들어 있다. 하나를 골라 읽는다.

**"세계에서 관광객 많은 나라는?" · "한국은 몇 위야?" ·
"다른 나라랑 비교하면"**

```bash
query.py --qid TS_01_08_001 --from 2020 --to 2022
```

**한국은 이 표에 없다.** 실제 국가는 1~50위 오십 곳이고 대한민국은
그 안에 없다(2022 기준). "한국 몇 위"에는 답할 수 없다고 말한다.

세 가지를 더 조심한다. **2023년부터는 국가별이 오지 않는다**
(2019년 203행 · 2022년 153행 · 2023년 2행). 국가별 순위는 2022년
까지다. 국가명이 `전체`인 합계 행이 섞여 있고 그 행의 순위는 0 또는
999다 — 정렬하면 1위로 올라온다. `구분`이 네 갈래(인바운드·아웃
바운드·관광수입·관광지출)이므로 **다 더하면 뜻이 없는 숫자**가 된다.

**"화천산천어축제 방문객 몇 명?"**

```bash
query.py --qid FE_01_01_005 --festival 화천산천어축제 --period 2024
```

축제는 연 단위다. 월을 넣으면 빈 배열이 온다.

**"강릉에 몇 명 왔어?"(이동통신 기준) · "현지인 빼고는?"**

```bash
query.py --qid BDT_01_01_004_4 --region 강릉시 --period 작년
```

세 갈래가 온다 — 현지인방문자(a) · 외지인방문자(b) · 전체방문자(a+b).
**다 더하면 두 배가 된다.** 이 저장소에서 '전체 방문자'를 부를 수 있는
유일한 자리다.

**`touDivCd=1` 은 전체가 아니라 현지인이다.** 오래 '전체'로 잘못
적혀 있었고 2026-08-24에 고쳤다. 관광객을 보려면 4(외부방문자 b+c)다.
`BDT_01_01_001`·`002` 의 기본값도 4로 바꿨다.

**"강릉 어느 동네를 많이 찾아봐?"(내비게이션)**

```bash
query.py --qid BDT_03_01_004_1 --region 강릉시 --period 작년
```

읍면동별 내비게이션 목적지 검색건수다. **`전년동기_검색건수` 는 늘
0이다** — 증감률을 계산하지 마라. 전년 대비를 보려면 기간을 두 번
불러 직접 견주어라. 검색은 방문이 아니다.

`BDT_03_01_003_1`(시도 안 시군구별)은 **시군구를 넣어도 앞 두 자리만
본다** — 강릉을 넣으면 강원도 시군구 표가 온다.

**"강릉 어느 동네에 사람이 몰려?" · "20대는 어디로 가?"**

```bash
query.py --qid SE_AG_01_01_001 --region 강릉시 --period 작년   # 읍면동 방문자
query.py --qid SE_AG_01_01_001 --region 강릉시 --period 작년 \
  --param GEN_CD=1 --param AGEG_DIV_CD=2029                   # 남성 20대
query.py --qid SE_AG_01_03_001 --region 강릉시 --period 작년   # 동별 연령 분포
```

**이 저장소에서 읍면동까지 내려가는 유일한 지표군이다.** 성·연령
코드가 방문자와 소비에서 다르다 — 방문자는 `1`/`2` 와 `2029`,
소비(`SE_AG_02_*`)는 `M`/`W` 와 `20` 이다. 틀린 체계를 보내면 빈
본문이 오거나 조용히 무시된다.

분포 지표는 값이 `방문자수`(P_TOU_NUM)이고 `읍면동_전체_방문자수`
는 행마다 반복되는 총계다. 후자를 더하면 여덟 배가 된다.

**"외국인이 숙소를 어떻게 평가해?" · "리뷰에 무슨 말이 많아?"**

```bash
query.py --qid NAT_11_03_009 --period 작년                          # 긍정
query.py --qid NAT_11_03_009 --period 작년 --param srchKwrdText=NEGATIVE
query.py --qid NAT_11_03_009 --period 작년 --param srchTypeText=Camp
```

**외국인이 남긴 숙박 리뷰의 감성 분석이다.** 관광지 리뷰가 아니다.
숙박 유형은 `''`(전체)·`Hotel`·`Motel`·`Pension`·`Resort`·
`GuestHouse`·`Camp`.

**사이트의 철자가 틀려 있다.** 긍정은 `POSTIVE`(I 가 빠짐)이고
올바른 철자 `POSITIVE` 를 넣으면 빈 배열이 온다. 카탈로그가 기본값을
`POSTIVE` 로 박아 두었으니 긍정은 그냥 부르면 된다.

**긍정과 부정에 같은 낱말이 나온다**('위치'가 양쪽 상위). 어느 쪽
표인지 반드시 적어라.

**그리고 부정이 긍정보다 많다** — 2024년 긍정 40.0% · 보통 10.2% ·
부정 49.8%(`NAT_11_03_008`). 키워드 목록만 보고 "좋게 평가한다"고
적으면 반대로 말하게 된다. 비율을 먼저 보여 주고 키워드를 그 안에서
읽어라.

**"외국인이 간편결제로 뭘 사?"**

```bash
query.py --qid NAT_12_01_002 --period 작년   # 업종 구성
query.py --qid NAT_12_01_003 --period 작년   # 지역 구성
```

신용카드와 **결제 수단이 다르다.** 2024년 간편결제는 의료웰니스업이
67.8%, 서울이 90.5%로 쏠려 있다. 이것을 "외국인 관광소비 구성"이라고
적으면 결제 수단 하나의 쏠림을 전체로 말하게 된다.

**"한국 사람 국내여행 얼마나 다녀?" · "1인당 몇 번?" · "국내여행
시장 규모"**

```bash
query.py --qid TS_03_01_003 --from 2018 --to 2025   # 경험률(%)
query.py --qid TS_03_01_004 --from 2018 --to 2025   # 전체 횟수(천회)
query.py --qid TS_03_01_012 --from 2018 --to 2025   # 1인 평균 지출(천원)
```

**설문조사다.** 이동통신·카드 같은 실측이 아니다. **기간을 네 자리
연도로 준다** — 연월을 넣으면 시작 연도가 빠지고, 한 해만 물으면
빈 배열이 온다. 전체(천회·천일·십억원)와 1인 평균(회·일·천원)은
**단위가 달라 그대로 나누면 안 된다.** `연령대='전체'` 행이 섞여 있다.

**"외래관광객 만족도는?" · "다시 온대?" · "얼마나 머물러?"**

```bash
query.py --qid TS_03_02_012 --from 2015 --to 2025   # 만족도
query.py --qid TS_03_02_015 --from 2015 --to 2025   # 재방문율
query.py --qid TS_03_02_011 --from 2015 --to 2025   # 체재 기간
```

**재방문율과 재방문 의향은 다르다** — 앞은 이미 다시 온 사람의 비율,
뒤는 오겠다고 답한 비율이다(2021년 64.7 대 88.3). 지출 경비의 단위를
사이트가 표기하지 않으니 달러라고 적지 마라.

**"외국인이 한국을 어떻게 생각해?" · "한국 하면 뭐가 떠오른대?"**

```bash
query.py --qid TAE_06_01_002 --from 2014 --to 2019 --limit 20  # 인지도·선호도
query.py --qid TAE_06_01_003 --from 2014 --to 2019 --limit 20  # 연상 도시·콘텐츠
```

**2019년에 멈춘 조사다.** 코로나 이전이므로 "요즘"이라고 적지 마라 —
인용할 때 조사 연도를 반드시 함께 적는다. 이 저장소에서 국가별
인식을 볼 수 있는 유일한 자리라 그래도 넣어 두었다.

`TAE_06_01_001`(이미지 평가)은 **67,857행**이라 항목으로 걸러야 한다.

**"관광수입 얼마야?" · "방한객 1인당 얼마 쓰나?" · "어느 대륙에서
많이 와?" · "국제선 탑승률"**

```bash
query.py --qid NAT_08_01_009 --period 작년   # 1인당 관광수입
query.py --qid NAT_08_01_011 --period 작년   # 대륙별 방한객
query.py --qid NAT_07_01_006 --period 작년   # 입국 공항·항구별
query.py --qid NAT_10_01_005 --period 작년   # 국제선 승객·탑승률
```

1인당 관광수입의 **분모에 승무원과 비관광 목적 입국자가 들어 있다** —
"관광객 1인당 지출"이 아니다. 단위도 다르다(관광수입 백만 달러,
1인당 달러). 국제선 표의 내국인 승객은 **추정값**이다.

**"방한객 남녀 비율은?" · "몇 살이 많이 와?" · "무슨 목적으로 와?" ·
"어느 공항으로 들어와?"**

```bash
query.py --qid TS_01_16_001 --period 작년       # 성별
query.py --qid TS_01_16_002_1 --period 작년     # 연령(10세 구분)
query.py --qid TS_01_16_003 --period 작년       # 입국목적
query.py --qid TS_01_16_004_NEW2 --period 작년  # 공항·항구
```

**승무원이 갈래에 섞여 있다.** 남녀 비율을 낼 때 빼라(2024년 1월
전체의 8%). **"방한객"과 "방한 관광객"은 다르다** — 입국목적이
관광인 사람은 2024년 1월 전체의 79%다.

같은 표에 `원달러_환율`과 `국제유가`가 함께 실려 있다. 방문자 수로
읽지 마라. `기간_환율_최소/최대`는 그 달 값이 아니라 조회 기간
전체의 최소·최대다.

**"작년에 해외로 몇 명 나갔어?" · "출국자 연령대"**

```bash
query.py --qid TS_01_17_004_New --period 작년       # 성별
query.py --qid TS_01_17_005_New_1 --period 작년     # 연령
query.py --qid TS_01_17_006_New_2 --period 작년     # 출국 공항·항구
```

**'전체'가 두 축에 다 있다.** 기준월에도 '전체' 행이 있고 갈래에도
'전체'가 있다 — 열두 달을 물으면 13개 달이 온다. 걸러내지 않고
더하면 네 배가 된다.

**"중국인이 관심 갖는 관광지는?" · "대만·홍콩 사람들은?"**

```bash
query.py --qid LN_03_01_062 --region 강릉시 --period 작년   # 중국어 간체
query.py --qid LN_03_01_063 --region 강릉시 --period 작년   # 중국어 번체
```

간체는 중국 본토, 번체는 대만·홍콩이다. **합치지 마라** — 같은
관광지가 두 번 세어진다. 영어권은 `060`, 일본어는 `061`, 내국인은
`064` 다. 값은 방문자 수가 아니라 대한민국구석구석 그 언어 페이지의
조회 수다.

**"다음 주말 사람 많을까?" · "무슨 요일에 붐벼?"**

```bash
query.py --qid LN_02_01_005 --region 강릉시 --period 작년
```

**세 가지를 반드시 함께 말한다.** ① 앞으로 5주치 요일별 집중률(%)
이고 35행을 다 더하면 100이다. ② 요청한 기간과 무관하게 늘 지금
기준으로 온다. ③ **사이트가 이 차트를 화면에서 숨겨 두었다**
(2024-01-09 고객요청). 서버는 아직 응답하지만 예고 없이 끊길 수 있다.

`LN_04_01_011`(향후 30일 지역 집중률)도 같은 자리인데, 값이
무엇인지 사이트가 밝히지 않는다 — **방문자 수로 옮겨 적지 마라.**

**"관광안내소에 뭘 물어봐?" · "무슨 말로 물어?"**

```bash
query.py --qid BZM_04_01_002 --period 작년   # 유형별(음식·쇼핑·교통…)
query.py --qid BZM_04_01_003 --period 작년   # 어권별(한국어·영어·중국어…)
query.py --qid BZM_04_01_001 --period 작년   # 시도별
```

**어권은 국적이 아니다** — '한국어'가 가장 많은데 내국인일 수도
재외동포일 수도 있다. 안내 건수이지 방문자 수가 아니다.

**빈 문자열을 보내면 죽는다.** `--param GUID_TYPE_NM=` 처럼 값 없이
주면 빈 배열이 온다 — 아예 주지 않거나 '전체'를 준다.

**"관광객 불편신고 어디가 많아?" · "무슨 불편이 제일 많아?"**

```bash
query.py --qid TS_01_12_006 --period 작년                    # 지역 순위
query.py --qid TS_01_12_006 --period 작년 --param selectDiv=2  # 국가 순위
query.py --qid TS_01_12_005 --period 작년                    # 유형별
```

시도 단위까지만 있다. 시군구는 없다. **국가 순위로 부르면 컬럼
이름은 그대로 시도명인데 값이 국가명**이므로 표에 축을 적어라.
`TS_01_12_005` 의 합계는 `중분류_건수` 로 낸다 — `대분류_건수` 는
중분류 행마다 반복되는 값이라 더하면 다섯 배가 넘는다.

**"관광 소비자 상담·위해 사고 얼마나 되나?"**

```bash
query.py --qid TS_01_09_003 --period 작년                     # 지역별 상담
query.py --qid TS_01_09_004 --period 작년                     # 지역별 위해
query.py --qid TS_01_09_002 --period 작년 --param location=2  # 위해 원인별
```

상담과 위해는 **다른 통계다**(2024년 13,209건 대 3,853건). `location`
은 장소가 아니라 나누는 축이다 — 1 품목 · 2 원인 · 3 부위 · 4 증상 ·
5 장소.

## 답할 수 없는 말, 그리고 대신 줄 수 있는 것

| 사용자가 묻는 것 | 대신 보여 줄 것 |
|---|---|
| "우리 카페 매출 오를까" | 그 시군구 음식업 카드소비 추세 + 방문자 추세 |
| "내년에 관광객 늘까" | 최근 24개월 추세. **연 단위 예측은 없다** |
| "다음 주말 사람 많을까" | `LN_02_01_005`(향후 5주 요일별 집중률). 아래 단서를 반드시 함께 말한다 |
| "경쟁 호텔 객실 수" | 그 시군구 전체 숙박 객실 수와 시설 수 |
| "임대료 얼마" | 없다. 데이터랩은 부동산을 다루지 않는다 |
| "이 관광지 후기 어때" | 검색량과 방문 집중률. **관광지 감성 분석은 없다** — 숙박 리뷰만 있다(아래) |
| "관광객 동선" | 관광지별 연관 관광지(개인 동선이 아니다) |

없는 것을 있는 것처럼 만들어 내지 않는다. 대신 가장 가까운 실측치를
주고, 그것이 질문과 어떻게 다른지 한 줄로 적는다.

## 통합시

수원·성남·안양·부천·안산·고양·용인·화성·청주·천안·포항·창원·전주.
열세 곳은 시 이름으로 물으면 지표의 절반쯤이 빈다. 스킬이 안내를
띄우면 구 단위로 다시 부를지 물어본다.

```bash
scan.py --region '전주시 완산구' --period 작년 --out /tmp/scan.html
scan.py --region '포항 북구'    --period 작년 --out /tmp/scan.html   # '시'를 빼도 된다
```

**구별 값을 더해 "시 전체"라고 적지 않는다.** 구 사이를 오간 사람이
구마다 세어져 합이 10%가량 부풀려진다(2024년 1월 수원 네 구 합
17,344,087 vs 수원시 14,883,969). 시 전체 숫자가 필요하면 모시 코드로
부른다 — 방문자·숙박 계열은 모시로도 값이 온다.

**시 코드로만 비는 지표 쉰셋의 목록(`docs/통합시-빈손.md`)은 소스
저장소에만 있다** — 배포본에는 `docs/`가 없다. 인출 계층이
`sggIntgYnFlag` 를 바꿔 한 번 되묻기 때문에 열여섯은 이제 시 코드로도
온다(읍면동 성·연령이 그렇다).

## 되물어야 하는 경우

| 상황 | 되묻는 말 |
|---|---|
| 지역 이름이 여러 곳에 걸린다 (강서구, 중구) | 후보 목록을 보여 주고 고르게 한다 |
| 타겟 국가 브리핑인데 업종을 말하지 않았다 | 업종을 묻는다. 가중치가 달라진다 |
| "전국"인지 "한 지역"인지 모호하다 | 범위를 묻는다. 전국 훑기는 몇 분 걸린다 |
| 통합시를 말했다 (전주시, 수원시 …) | 시 전체로 볼지 구 하나로 볼지 묻는다 |

지역·기간은 되묻지 않고 기본값으로 진행해도 된다. **업종과 범위는
되묻는다** — 결과가 통째로 달라지기 때문이다.
