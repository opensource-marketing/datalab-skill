# 데이터랩 안내 창구

이 저장소는 한국관광 데이터랩(datalab.visitkorea.or.kr)의 데이터를
웹사이트에 접속하지 않고 쓰기 위한 스킬 모음이다. 이 스킬은 그중
**어디로 갈지**를 정해 준다.

## 1. 처음이라면

```bash
python3 {SKILLS_DIR}/datalab-guide/scripts/doctor.py
```

설치·연결·로그인·데이터 표를 순서대로 보고 **지금 해야 할 일 한 가지**를
알려 준다. 다 끝나면 바로 질문해도 된다.

**로그인은 필요 없다.** 검증된 지표 348개가 **전부 공개**이고 실호출
77가지가 로그인 없이 통과한다. 한동안 마지막까지 남아 있던
`NAT_07_01_018` 도 이제 쿠키 없이 값을 준다.

로그인이 쓰이는 자리는 하나다 — **회원 전용 화면에서 새 지표를
찾아낼 때**(`datalab-auth`). 데이터를 받기 위해서가 아니다.
빅데이터 메뉴는 브라우저로 열려면 로그인해야 하지만 그 데이터
API 는 공개다.

## 2. 질문을 스킬로 옮기는 표

사용자의 말이 왼쪽 칸에 걸리면 오른쪽 스킬을 쓴다.
**여러 개가 걸리면 가장 좁은 것을 먼저 쓴다.**

| 사용자가 이렇게 말하면 | 쓸 스킬 |
|---|---|
| "○○에 가게/호텔 내도 될까", "○○ 관광시장 어때", "○○랑 △△ 중 어디" | `region-market-scan` |
| "○○에 누가 오나", "○○ 방문객 특성", "얼마나 머무나", "뭘 소비하나" | `region-visitor-profile` |
| "어느 나라를 노릴까", "인바운드 타겟 국가", "면세점/호텔 타겟 시장" | `inbound-country-brief` |
| "일본인/중국인이 많이 가는 지역", "○○인 노린 매장 입지" | `inbound-region-scan` |
| "의료관광 시장", "MICE 규모", "한류", "야간관광", "크루즈" | `theme-market-brief` |
| "○○ 인구감소 심각해", "관광이 ○○ 먹여 살리나", "지역소멸" | `region-vitality-brief` |
| "요즘 관광 어때", "전국 상황", "어디가 뜨고 있어" (축 없음) | `national-tourism-brief` |
| "관광 불편신고", "관광객이 뭘 불편해해", "안내소에 뭘 물어봐", "외국인이 숙소를 어떻게 평가해" | `tourism-service-brief` |
| "해외에서 한국 관광 반응 어때", "어느 나라가 많이 언급해", "SNS에서 긍정적이야", "어떤 해시태그" | `global-social-brief` |
| "○○ 방문자 몇 명", "○○ 1위 지역", 숫자·표·순위 하나 | `datalab-query` |
| "그런 데이터 있어?", 새 지표를 찾아야 할 때 | `datalab-fetch` |
| "로그인이 필요합니다", "세션 만료" | `datalab-auth` |

**지역을 묻는 스킬이 셋이라 헷갈리기 쉽다.** 묻는 것이 서로 다르다:

| 사용자가 알고 싶은 것 | 스킬 |
|---|---|
| 여기 오는 사람은 누구인가 | `region-visitor-profile` |
| 여기서 사업할 만한가 | `region-market-scan` |
| 여기가 버티고 있는가 (지자체 정책) | `region-vitality-brief` |

**국가를 묻는 스킬도 셋이라 갈린다.**

| 사용자가 알고 싶은 것 | 스킬 |
|---|---|
| 어느 나라를 노릴까 (5축 점수로 줄 세우기) | `inbound-country-brief` |
| 그 나라 사람이 우리나라 어디로 가나 | `inbound-region-scan` |
| 그 나라가 한국을 **어떻게 이야기하나** (오기 전) | `global-social-brief` |

마지막 것은 **사람 수가 아니라 말의 수**를 센다. 언급량이 많은
나라가 곧 많이 오는 나라는 아니다 — 방문자 규모를 함께 물어야 한다.

리포트(HTML)를 만드는 스킬과 숫자 하나를 답하는 스킬을 헷갈리지 말 것.
**"몇 명이야?"에 리포트를 만들어 주면 과잉이다.** `datalab-query`를 쓴다.

## 3. 데이터랩이 답할 수 있는 것과 없는 것

초보자가 가장 자주 실망하는 지점이다. 먼저 선을 그어 주는 편이 낫다.

**답할 수 있다**

- 어느 지역에 몇 명이 왔나 (통신·카드 기반 추정, 월 단위, 시군구)
- 그들이 어디서 왔나, 몇 살인가, 얼마나 머물렀나
- 어디에 얼마를 썼나 (업종별 카드 소비)
- 어느 나라에서 몇 명이 방한했나, 무엇을 하러 왔나
- 관광사업체가 몇 개이고 늘고 있나 (숙박·여행업 등)
- 관광지·축제별 방문 규모와 방문객 구성
- 의료관광·MICE·한류·야간관광 같은 세그먼트의 전국 규모
- **읍면동까지** 내려간 방문자·소비·검색 (성별·연령대로 다시 자를 수 있다)
- 방한객이 누구인가 — 성별·연령·입국목적·들어온 공항
- 관광불편신고와 소비자 상담·위해 건수 (지역별·유형별·국적별)
- 국민여행조사·외래관광객조사 (경험률·만족도·재방문율, 설문조사다)
- 외국인이 남긴 **숙박 리뷰의 감성 분석**(긍정·부정 키워드)
- **해외 소셜미디어에서 한국 관광을 얼마나·어떻게 이야기하나**
  (26개국 언급량·반응·긍부정·해시태그·플랫폼 점유율)
- 그 나라 사람들이 어디로 여행 가고 **그중 한국이 몇 번째인가**
- 방한 정보를 어느 플랫폼에서 얻고 어느 사이트에서 상품을 사나
- 세계 관광시장 전체 규모(국제관광객 도착수·관광수입)
- 세대별 인기관광지 30위 (20대와 60대의 표가 겹치지 않는다)

**답할 수 없다**

- 특정 가게·브랜드의 매출이나 점유율
- 연 단위 예측 (대부분의 지표는 과거 실적이다). 다만 **향후 5주
  요일별 방문 집중률**은 있다 — 사이트가 화면에서 숨겨 둔 차트라
  예고 없이 끊길 수 있다는 것을 함께 말해야 한다
- 관광지 리뷰의 감성 분석 (숙박 리뷰만 있다)
- 경쟁사 정보, 임대료, 부동산 시세
- 관광객 개개인의 동선이나 신원
- 아직 발표되지 않은 달 (아래 4번)
- 소셜미디어 언급량을 **방문자 수로 환산하는 것** — 나라마다
  소셜을 쓰는 정도가 달라서 비례하지 않는다

답할 수 없는 질문에는 **비슷한 답이 되는 지표를 대신 제안**한다.
예: "우리 카페 매출 오를까" → 그 시군구의 음식업 카드소비 추세와
방문자 수 추세를 보여 주고, 판단은 사용자에게 남긴다.

## 4. 초보자가 반드시 알아야 할 함정 다섯

### 기간 — 빈 결과는 "없다"가 아니라 "아직"일 때가 많다

데이터랩은 아직 발표되지 않은 달을 물어도 오류를 내지 않는다.
빈 배열을 돌려준다. 그래서 "2026년 강릉시 관광사업체"가 **0개처럼**
보인다. 지표마다 언제까지 나와 있는지 확인한다:

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/period.py show 환자
python3 {SKILLS_DIR}/datalab-fetch/scripts/period.py latest BY_TH_MEDIC_001_001
```

지표 348개 중 325개의 수록 시점을 알고 있고, 그중 239개는 지난달까지
확인됐다. 뒤처지는 것은 연 단위 지표다 — 외국인 환자 수와 MICE
개최건수가 그렇다. 남은 23개는 기간 파라미터를 받지 않아 시점 개념이
없다(메인 화면 카드·인기 랭킹).

기간은 사람 말로 써도 된다 — `2024년 1월`, `작년 상반기`, `작년 12월`,
`올 상반기`, `지난달`, `최근12개월`, `2024Q3`, `2024~2025`. 지역·국가도
마찬가지다 — `서울 중구`, `강원도 강릉시`, `포항 북구`, `성남 분당`,
`일본인`, `중국인 관광객`, `USA`, `UAE`. 리포트 스킬은 `--period`,
`--region`, `--country` 로 받는다.

`이번달`은 알아듣고 없다고 말한다 — 어떤 지표에도 이번 달 값은 없다.

### 조회 축 — 틀리면 오류가 아니라 빈 배열이다

지표마다 받는 단위가 다르다. 시군구(5자리)·시도(2자리)·국가·관광지·
축제·전국. 야간관광에 시군구 코드를 넣으면 조용히 빈 배열이 온다.
`index.py show <qid>` 가 그 지표의 축을 알려 준다.

### 이름 — 지표 이름은 출처이지 근거가 아니다

컬럼 이름이 "방문자수"인데 실제로는 집중률(%)인 지표가 있다.
가장 크게 어긋난 것은 `KOR_VST_TOU_NUM`("방한 관광객수")인데 값은
**세계 전체** 국제관광객이었다 — 2018년 14.13억명이다. 이름만 보고
옮겨 적었으면 90배 부푼 숫자가 "방한객"으로 실린다.

검증된 카탈로그 **348개**는 실제 호출과 산술 교차확인을 거친 것이고,
색인에만 있는 **517개**는 이름만 긁어 온 것이다. 리포트에 쓰기 전에
반드시 확인한다.

### 통합시 — 시 이름으로는 값이 반만 온다

수원·전주·창원 같은 통합시 열세 곳은 코드가 둘로 산다. 시 전체 코드
(전주시 52110)와 구 코드(완산구 52111, 덕진구 52113)다. 관광사업체·
인기관광지·유사지역은 **구 코드로만** 값이 온다. 방문자 수는 시 코드로도
온다. 그래서 같은 리포트 안에서 어떤 표는 차 있고 어떤 표는 빈다.

```
--region 전주시          →  수록 11/22
--region '전주시 완산구' →  수록 21/22
```

**한때 더 많이 비었는데 그것은 지표 탓이 아니었다.** `sggIntgYnFlag`
가 시 쪽과 구 쪽을 가르는데 카탈로그가 "N"을 못 박고 있어서 열여섯
지표가 통째로 빈 배열이었다(읍면동 성·연령 열둘이 그랬다). 인출
계층이 이제 모시 코드가 빈손이면 한 번 되묻는다.

그래도 남는 빈손이 있다. 어느 지표가 시 코드로 비는지 적은 목록
(`docs/통합시-빈손.md`, 수원 53개 · 창원 57개, **하한으로 읽는다**)은
**소스 저장소에만 있다** — 배포본에는 `docs/`가 없다.

**구별 값을 더해 "시 전체"라고 적지 않는다.** 구 사이를 오간 사람이
구마다 세어져 합이 10%가량 부풀려진다(2024년 1월 수원 네 구 합
17,344,087 대 수원시 14,883,969).

스킬들이 통합시를 알아보고 먼저 알려 준다. 그 안내가 뜨면 구 단위로
다시 부를지 사용자에게 물어본다.

### 합계 — 표 안에 합계 행이 섞여 있다

데이터랩의 표는 **합계 행을 따로 주는 것이 기본**이라고 봐야 한다.
`'전체'`·`'합계'`·`'글로벌'`·`'전체방문자(a+b)` — 이름은 달라도 같은
모양이고, 걸러내지 않고 더하면 **정확히 두 배**가 된다.

비율도 마찬가지다. 인기관광지 표의 `TOTAL_NUM` 은 전국 전체가
아니라 **그 표 30곳의 합**이라, "에버랜드가 전국 검색의 9%"로 읽으면
크게 부푼다.

**표를 옮기기 전에 카탈로그의 `caution` 을 읽는다.** 리포트는 그것을
표 옆에 그대로 싣는다:

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/index.py show LN_02_01_009
```

## 7. 스킬이 실패했을 때 읽는 순서

1. 값이 비었다 → 기간을 의심한다 (`period.py latest <qid>`)
2. 여전히 비었다 → 축을 의심한다 (`index.py show <qid>`)
3. **값이 있는데 이상하다 → 캐시를 의심한다.** 같은 조건의 응답은
   작업 공간의 `data/raw/`(기본 `.datalab/data/raw/`, 정확한 경로는
   `doctor.py`가 보여 준다)에 캐시되어 다시 부르지 않는다(같은 리포트
   재실행이 39초 → 0.6초). 데이터랩이 지난달 값을 정정했다면 옛 값이
   계속 나온다. 그 지표의 캐시만 지우고 다시 돌린다:

   ```bash
   rm -f .datalab/data/raw/<qid>_*.json      # 지표 하나만
   rm -rf .datalab/data/raw/                 # 전부. 지워도 다시 만들어진다
   ```

   `DATALAB_HOME`으로 작업 공간을 옮겼다면 `.datalab/` 대신 그 경로를 쓴다.

   빈 배열은 처음부터 캐시하지 않으므로, "비었다"는 캐시 탓이 아니다.
4. **통합시인데 표 몇 개가 비었다** → 그 지역이 통합시인지 본다.
   시 코드로만 비는 지표 목록(`docs/통합시-빈손.md`)은 소스
   저장소에만 있다 — 배포본에는 `docs/`가 없다.
   구 코드로 다시 부르면 대개 채워진다
5. **값이 다른 지표와 안 맞는다** → 파라미터를 다 보냈는지 본다.
   데이터랩은 빠뜨린 파라미터를 오류로 알려 주지 않고 **기본값이나
   뒤섞인 값**을 준다. 실제로 "기준 시점 컬럼이 없다"고 적고 뺐던
   지표 넷이 파라미터 하나를 안 보낸 것이었다
6. "로그인이 필요합니다" → `datalab-auth`
7. 그 외 → `doctor.py`

## 8. 카탈로그가 오늘도 맞는지 보는 도구

단위 테스트는 네트워크를 쓰지 않는다. **그래서 데이터랩이 바뀌면
테스트는 전부 통과하는데 사용자만 빈 리포트를 받는다.** 카탈로그를
손보는 개발자용 검사 도구는 소스 저장소에만 있다.

**"통과했다"고 말하기 전에 실제로 돌리고 출력을 본다.**
