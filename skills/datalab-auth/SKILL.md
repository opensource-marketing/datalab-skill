# 데이터랩 인증

## 먼저: 대개 로그인은 필요 없다

**검증된 지표 348개가 전부 공개다.** 로그인 없이 실호출 77가지가 모두
통과한다 — 소스 저장소의 `tests/smoke.py`로 확인했다(배포본에는
`tests/`가 없다). 마지막까지 `auth: session`으로
남아 있던 `NAT_07_01_018`도 2026-08-23 쿠키 없이 열한 행을 줬다.

그러니 "값이 안 나온다"의 원인을 로그인에서 찾지 마라. 열에 아홉은
조회 축이 틀렸거나(빈 배열이 온다) 아직 발표되지 않은 기간이다.

## 화면과 API 는 따로 막힌다

**빅데이터 메뉴(이동통신·신용카드·내비게이션)는 브라우저로 열려면
로그인해야 하지만, 그 데이터 API 는 공개다.** `BDT_*` 지표를 오늘도
쿠키 없이 부른다. 화면이 회원 전용이라고 해서 데이터가 막힌 것이
아니다.

그래서 **로그인이 필요한 이유는 데이터를 받기 위해서가 아니라 qid 를
알아내기 위해서**다. 회원 전용 화면에서 새 지표를 찾아낼 때만 쓴다.
한 사람이 한 번 찾아내 카탈로그에 넣어 두면 그 뒤로는 아무도 로그인하지 않는다.

## 그러면 이 Skill 은 누구에게 필요한가

| | 로그인 |
|---|---|
| 조회·순위·리포트를 쓰는 사람 | 필요 없다 |
| 카탈로그를 넓히는 사람(새 지표 발굴) | 필요하다 |

**그래도 지우지 않는다.** 데이터랩이 언젠가 어떤 API 를 회원 전용으로
바꾸면 `SessionExpired` 가 뜨고, 여섯 개 Skill 이 그 상황에서 이곳을
가리킨다. **자동 재로그인을 하지 않는다**는 규칙이 이 안내가 있다는
전제 위에 서 있다.

## 로그인하기

```
! python3 {SKILLS_DIR}/datalab-auth/scripts/login.py
```

**`!`를 붙여 실행한다.** Claude가 대신 실행하지 마라 — 브라우저 창이 뜬다.

1. 창이 뜨면 데이터랩에 로그인한다
2. **브라우저 창을 닫는다**
3. 세션이 작업 공간(기본 `.datalab/.auth/storage_state.json`,
   `DATALAB_HOME`으로 옮길 수 있다)에 저장된다

끝났다는 신호로 창 닫기를 쓰는 이유가 있다. 터미널에서 Enter를 받는
방법을 먼저 썼는데, Claude Code에서 `!`로 실행하면 표준입력이 대화형이
아니라 그 자리에서 EOF가 난다 — 사용자는 브라우저를 보고 있는데
스크립트는 이미 끝나 버린다.

아이디와 비밀번호는 브라우저에만 들어간다. 이 스크립트도 Claude도
그 값을 읽지 않는다.

한 번 로그인하면 브라우저 프로필(작업 공간의 `.auth/browser`, 기본
`.datalab/.auth/browser`)이 기억한다. 다음에 실행하면 이미 로그인된
채로 열린다.

## 확인하기

```bash
python3 {SKILLS_DIR}/datalab-auth/scripts/check_session.py
```

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 유효 | 살아 있다 | 없음 |
| 만료 | 서버가 거부한다 | 다시 로그인 |
| 확인불가 | 네트워크·사이트 문제로 판단 불가 | 네트워크를 먼저 확인. **재로그인이 답이 아니다** |
| 미확인 | 세션 파일이 없다 | 필요하면 로그인 |

## 로그인 여부를 어떻게 확인하나

**저장할 때는 확인하지 않는다.** 사용자가 Enter를 눌렀으면 로그인한
것으로 보고 그대로 저장한다. 확인은 저장한 뒤에 알려 주기만 한다.

자동 판정으로 저장 여부를 정하던 때가 있었는데, 판정이 틀릴 때마다
멀쩡히 로그인한 사용자의 세션을 버렸다. 세 가지 방식이 차례로 틀렸다:

| 방식 | 왜 틀렸나 |
|---|---|
| 쿠키 `key`가 생겼는가 | 데이터랩은 로그인해도 쿠키를 새로 만들지 않는다. 세션 쿠키 하나가 서버 쪽에서 인증됨으로 바뀔 뿐이다 |
| 인증 지표가 값을 주는가 | 그 지표가 공개로 바뀌자 로그인 안 한 세션도 늘 "유효"가 됐다 |
| 막힌 화면이 열리는가 | 지금 `check_session`이 쓰는 방식. 알려 주는 데만 쓰고 저장을 막지 않는다 |

`check_session`은 로그인해야 열리는 화면(빅데이터 > 이동통신 > 지역별
방문자수)과 누구나 열리는 대조 화면(지역별 관광 현황)을 함께 열어 본다.
대조 화면까지 비면 "만료"가 아니라 "확인불가"다 — 네트워크 문제를
로그인 만료로 뭉개면 사용자가 멀쩡한 세션을 지우게 된다.

## 문제가 풀리지 않을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `브라우저를 실행하지 못했습니다` | Chromium 미설치 | `python3 -m playwright install chromium` |
| 창을 닫아도 반응이 없음 | 다른 창이 남아 있다 | 그 브라우저의 창을 모두 닫는다 |
| 로그인했는데 로그인 화면이 다시 뜸 | 사이트가 `document.referrer`로 돌아가는데 그 값이 비었을 때 생긴다 | 이 스크립트는 첫 화면을 거쳐 들어가므로 해당 없음. 직접 주소로 열었다면 그것이 원인이다 |
| 저장했는데 `로그인되지 않은 세션` | 로그인이 끝나기 전에 창을 닫았다 | 로그인 완료를 확인하고 다시 실행 |
| 사이트가 알림을 띄웠는데 안 보임 | 해당 없음 | 이 스크립트는 알림 내용을 `[사이트 알림]`으로 찍는다 |

## 하지 않는 것

- **아이디·비밀번호를 묻지 않는다.** 로그인은 브라우저에서만 일어난다
- **자동 재로그인을 하지 않는다.** 세션이 만료되면 멈추고 사용자에게 넘긴다
- **작업 공간(기본 `.datalab/`, 그 안의 `.auth/`)을 커밋하지 않는다.**
  세션 쿠키와 브라우저 프로필이 들어 있다
