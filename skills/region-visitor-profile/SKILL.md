# 지역 방문객 프로파일

시군구 하나를 깊이 이해하기 위한 리포트를 만든다. 지역 간 순위를 매기지 않는다.

## 빠른 사용법

```bash
python3 {SKILLS_DIR}/region-visitor-profile/scripts/visitor_profile.py \
  --region 종로구 --from 202401 --to 202412 --out report.html
```

`--region`에는 시군구 이름이나 5자리 코드를 넣는다. 이름이 여러 지역에 걸리면
후보를 보여주고 멈춘다 — 임의로 하나를 고르지 않는다.

| 옵션 | 뜻 |
|---|---|
| `--region` | 시군구 이름 또는 5자리 코드 (필수) |
| `--from` / `--to` | YYYYMM. 월 단위 최대 18개월 (필수) |
| `--out` | 출력 HTML 경로 (필수) |
| `--no-compare` | 전년·유사지역 비교를 건너뛴다. 비교기준은 전년 동기와 유사지역을 더 부르므로 호출이 2배쯤 는다 — 2026-08-23 실측(캐시가 빈 지역): **16회 10초 → 36회 15초**. 캐시가 차 있으면 둘 다 0.4초다. 빠른 확인용 |

## 리포트 구성

| 섹션 | 답하는 질문 |
|---|---|
| 규모·추세 | 방문자가 늘고 있나, 성수기는 언제인가 |
| 누구 | 어느 성·연령대가 오나, 외국인은 어느 나라에서 오나 |
| 어디서 | 상권 반경은 어디까지인가, 근거리형인가 원거리형인가 |
| 체류 깊이 | 스쳐가는 곳인가 머무는 곳인가 |
| 소비 | 어느 업종에 돈이 흐르나, 전국에서 몇 %인가 |
| **전국과 견주면** | **이 값이 전국 기초지자체 평균의 몇 배인가** |
| **동네까지 보면** | **시군구 안 어느 읍면동에 누가 모이나** |

### 동네까지 보면

**이 저장소에서 시군구 아래로 내려가는 유일한 자리다.** 성·연령별
조회 화면(`SE_AG_*`)이 읍면동 단위를 준다.

세 표가 실린다 — 읍면동별 방문자 수, 읍면동별 연령 분포, 읍면동별
성별 분포.

읽을 때 반드시 함께 말할 것 셋:

- **외지인만이다.** `TOU_DIV_NM` 이 '외지인' 하나로 고정이라 현지인이
  빠져 있다. 앞 섹션의 방문자 수와 모집단이 다르다
- **읍면동을 다 더해도 시군구가 되지 않는다.** 동 사이를 오간 사람이
  동마다 한 번씩 세어진다(강릉시 2024년 외지인 기준 1.99배)
- **분포 표의 값은 `방문자수`(P_TOU_NUM)다.** 같은 행의
  `읍면동_전체_방문자수` 는 그 동 전체가 행마다 반복되는 값이라
  더하면 여덟 배가 된다

성·연령으로 좁혀 보려면 리포트가 아니라 `datalab-query` 를 쓴다 —
`--param GEN_CD=1 --param AGEG_DIV_CD=2029` 처럼. **코드 체계가
소비 지표와 다르다**(그쪽은 `M`/`W` 와 `20`).

### 전국과 견주면

앞 섹션들이 "이 지역이 얼마나"를 보여 준다면 이 표는 "**남들보다
어떤가**"에 답한다. 데이터랩이 같은 값에 전국 기초지자체 평균을 한 행
더 얹어 주는 지표가 있어서, 리포트가 둘을 한 줄로 합치고 배수를 낸다.

```
기준월    전국 평균   강릉시   배수
202401      1,147     2,039   1.78배
202403      1,337     2,697   2.02배
```

체류시간·숙박방문자 비율을 전체와 외국인 두 갈래로 싣는다. 강릉시는
체류시간이 전국 평균의 1.5~2.0배이고 숙박방문자 비율은 3.2~3.5배다.

**숙박은 외지인과 외국인 두 표로 싣는다.** 강남구는 외지인 숙박
비중이 3.4%인데 외국인은 15.6%다 — 같은 지역이 내국인에게는 스쳐
가는 곳이고 외국인에게는 묵는 곳이다. 외지인만 보면 "숙박 수요가
없다"고 읽는다.

**'전체' 지표(`LN_02_01_013`)는 일부러 뺐다.** 평균 숙박일이 외국인
값과 소수점 둘째 자리까지 같아서(강남구 2024년 열두 달 전부), 셋을
나란히 실으면 "전체와 외국인이 똑같다"는 잘못된 문장이 표에서 저절로
만들어진다.

알아야 할 것 셋.

- **전국 평균은 시군구들의 평균이지 전국 합계가 아니다.** 합계로 읽으면
  자릿수가 어긋난다.
- **체류시간 단위는 분이다.** 2,039분은 34시간이다. 사람에게 말할 때는
  시간으로 바꿔라.
- **외국인 값은 따로 봐야 한다.** 강릉시 2024-01 체류시간이 전체
  2,039분인데 외국인은 5,482분(91시간)이다. 외국인은 한 번 오면 훨씬
  오래 머문다. 그 표의 전국 평균도 외국인 기준이라 전체 표의 평균과
  섞으면 안 된다.

한쪽 값만 온 달은 표에서 뺀다 — 0으로 채우면 그 달만 뚝 떨어진 것처럼
보이기 때문이다.

## 기간 대표값 계산

여러 달치 값을 기간 하나의 대표값으로 요약할 때, 지표마다 계산 방식이 다르다.

| 방식 | 대상 지표 | 계산 |
|---|---|---|
| 단순평균 | 방문자수, 숙박방문자수, 평균숙박일 | 월별 값의 평균 |
| 가중평균 | 숙박비율(순방문자수로 가중), 평균체류시간(방문자수로 가중) | Σ(월별 값 × 가중치) / Σ가중치 |
| 비율 | 전국대비 소비비중 | Σ월별 분자 / Σ월별 분모 |

비율형 지표를 단순평균하면 방문자가 적은 달이 많은 달과 같은 무게로 들어가
기간 전체 비율과 어긋난다. 실측에서 강릉시 전국대비 소비비중은 단순평균과
합계 비율 사이에 13.9% 차이가 났고(0.117% vs 0.101%), 고창군은 데이터랩
사이트가 월별 값을 소수 둘째 자리로 반올림해 내려주는 탓에 단순평균이
정확히 `0.000%`가 됐다(실제는 0.005%).

**평균숙박일만은 예외로 단순평균이다.** 가중치로 쓸 절대 규모 컬럼이
응답에 없어 가중평균을 만들 수 없기 때문이다. 이 지표의 기간 대표값은
다른 지표보다 월별 변동에 더 민감하게 흔들릴 수 있다.

## 해석 규칙

**종합점수가 없는 것은 의도다.** 209개국을 줄 세우는 인바운드 브리핑과 달리
여기서는 한 지역을 이해하는 것이 목적이다. 종합점수는 정보를 버리기만 한다.
대신 모든 추이 지표에 **전년 동기 대비**와 **유사지역 대비**(데이터랩이 판정한
유사지역 상위 3곳의 평균)를 붙인다.

**"비교기준 없음"은 값이 나쁘다는 뜻이 아니다.** 전년 데이터나 유사지역 데이터를
가져오지 못했다는 뜻이다.

**소비 수치는 외국인 카드 사용액 기준이다.** 데이터랩이 **시군구 단위**
내국인 카드소비 지표를 내렸다(8개 qid 모두 0바이트). 이 리포트에서 내국인
소비를 읽어낼 수 없다.

다만 **시도 단위**로는 남아 있다. 야간관광 지표 `BY_TH_NIGHT_TOUR_002_002`의
`CNSM_AMT`가 시도별 월별 관광소비 총액을 현지인·외지인·외국인으로 나눠 준다
(원 단위). 사용자가 내국인 소비를 물으면 "없다"고 하지 말고 시도 단위로
`datalab-query`를 쓰라고 안내하라. 리포트 소비 섹션에
같은 경고가 붙어 있다.

**모든 수치는 추정치다.** 이동통신·신용카드·내비게이션 데이터 기반이며 실측
방문자 수가 아니다. 절대값보다 추세와 비중을 보라.

**수록률을 먼저 본다.** 리포트 하단 "데이터 수록 현황"에 시도한 지표 중 몇 개가
실제로 들어왔는지와, 빠진 지표의 사유가 있다. 수록률이 낮은 리포트로 결론을
내리지 마라.

**표는 20행에서 잘린다.** 방문자 거주지 분포(263행)와 외국인 국적별 분포
(25행)처럼 원래 행이 많은 지표는 크기순으로 정렬한 뒤 상위 20행을 보여주며,
캡션이 "~기준 상위 20행"이라고 밝힌다. 정렬 기준이 정해지지 않은 지표는
앞에서부터 20행만 보여주고 캡션이 "크기순으로 정렬된 것이 아닙니다"라고
낮춰 말한다 — 이 경우 표에 없는 나머지 행에 더 큰 값이 있을 수 있다.

**통합시는 코드가 두 층이다.** 경기도 대도시(고양·부천·성남·수원·안산·안양·용인·화성)는
산하 구를 합친 코드(예: 고양시 `41280`)와 구별 코드(덕양구 `41281`, 일산동구 `41285`,
일산서구 `41287`)가 함께 있다. **둘 다 조회된다** — 덕양구 단독 조회도 12개 지표가
모두 나오는 것을 실호출로 확인했다.

그래서 `--region 고양시`처럼 시 이름만 넣으면 본체와 산하 구가 모두 걸려
후보 4건을 보여주고 종료코드 2로 끝난다. 어느 쪽을 원하는지 정확히 지정하라 —
합산값은 코드(`41280`)로, 구 단위는 구 이름(`덕양구`)으로 넣는다.
**세종특별자치시는 아예 조회할 수 없다.** 데이터랩이 세종을 산하 시군구가
없는 단일 자치단체로 취급해 시군구 코드 마스터에 항목 자체가 없다.
`--region 세종`은 "일치하는 지역이 없습니다"로 끝난다.

## 세션이 만료되면

**종료코드 3은 세션 만료 때문에 지표를 하나도 못 가져왔을 때 나온다.**
일부 지표만 실패하면 리포트는 만들어지고(종료코드 0) 리포트 상단에 만료
경고가 붙는다. 현재 이 스킬이 쓰는 12개 지표는 전부 `auth: public`이라
로그인이 필요 없으므로, 실제로는 발생하지 않는다.

만료 경고가 뜬다면 자동 재로그인을 시도하지 말고 `datalab-auth` 스킬로 위임한다.

```bash
python3 {SKILLS_DIR}/datalab-auth/scripts/check_session.py   # 진단
python3 {SKILLS_DIR}/datalab-auth/scripts/login.py           # 갱신
```

종료 코드 3이 세션 만료다. 4는 인출 실패 또는 수록 지표 0개, 2는 인자 오류.

## 데이터 원천

`datalab-fetch` 스킬의 `catalog/loc_qid_catalog.yaml`에 지표 12개의 파라미터와
컬럼 의미가 있다. 다른 지역 지표를 추가하려면 그 카탈로그를 늘린다 —
qid를 코드에 직접 박지 마라.

## 기간 쓰는 법

`--period` 로 사람 말을 그대로 쓸 수 있다. `--from`/`--to` 와 함께 쓸 수는 없다.

| 쓰는 말 | 풀리는 기간 |
|---|---|
| `--period 작년` | 지난 달력 연도 전체 |
| `--period 올해` | 올해 1월부터 지난달까지 (지표가 더 짧으면 그 지표까지) |
| `--period 최근12개월` | 지난달부터 거꾸로 12개월 |
| `--period 2024` | 2024-01 ~ 2024-12 |
| `--period 2024상반기` / `2024Q3` | 반기 · 분기 |
| `--period 202401-202412` | 직접 지정 |

**지표마다 데이터가 나와 있는 마지막 달이 다르다.** 아직 발표되지 않은
달을 물으면 데이터랩은 오류가 아니라 빈 배열을 준다. 확인:

```bash
python3 {SKILLS_DIR}/datalab-fetch/scripts/period.py show 사업체
python3 {SKILLS_DIR}/datalab-fetch/scripts/period.py latest LN_04_01_022
```
